# 白の宿 — 3D ホテル案内実験

小さな3階建てホテルのチェックイン後案内を、軽量な Three.js / React Three Fiber で試す実験です。

- ホームから宴会場・浴場・トイレ・自分の部屋へすぐ案内
- 1F ロビー / 2F 客室5室 / 3F 共用施設の俯瞰と室内ビュー
- 館内の3Dビューはドラッグ回転・ピンチ拡大に対応（コンシェルジュは正面固定）
- 写実的な3Dコンシェルジュを胸から上で表示。初回はお辞儀してから音声案内し、話し終わると微笑んで首を傾ける
- 汐白島のイラスト地図と八つの観光地、モデルコースをホテル周辺案内として表示
- 観光地を選ぶと説明を表示。「案内を聞く」で特徴・移動時間・おすすめ時間を音声案内

## 使い方

ラボのホームから **白の宿** を開くか、`/#/experiments/shiro-yado` にアクセスします。

1. 「お部屋でゆっくり」または「部屋を設定」で部屋番号を設定（最初の案内起点は 1F ロビー）
2. 下部のクイック案内で 宴会場 / 浴場 / トイレ / お部屋 へ移動
3. 「到着したので現在地を更新」すると、次の案内の起点が変わります
4. ホームのコンシェルジュメニューから案内項目を選ぶと、選択言語の音声と口の動きで案内します
5. 「汐白島の観光案内」から地図と観光地を開き、各地の音声案内を再生できます

## ライブラリ

- `three` / `@react-three/fiber` / `@react-three/drei` … 館内3DとGLBコンシェルジュ
- `zustand` … 部屋と現在地の `localStorage` 保存
- Web Speech API … ブラウザ内蔵の音声合成（選択した言語の音声が必要）

API 呼び出しはありません。施設データはすべてこのフォルダ内の架空データです。

## コンシェルジュのモデルと動作

- `public/models/shiro-yado/hotel-concierge.glb` は参照画像からローカルで制作・補正したモデル（6.8 MB）。18本のボーンと `Idle` / `Bow` / `LookAround` の3クリップを含み、テクスチャもGLB内に格納する。モデルの取得に外部3DサービスやSitesのURLは使わない。
- GLBのGit blob SHA: `61d898458f2ee6fc46ae3c79cc7651c8afedd0db`。今回制作したファイルをそのまま使用する。
- 初回と使用言語を変えた直後は `Bow` の完了を待ち、その後に案内を読み上げる。話題の選択・再生はクリックから直接発話し、完了時に毎回笑顔になる。
- `concierge-playback.ts` が音声の準備・発話・正常終了・中断を区別する。停止、ミュート、ページ移動、画面非表示では後続の動作を取り消す。古い発話のイベントで新しい案内を終了しない。
- 唇の開閉と口角・頬の変形は `scene/concierge-mouth.ts`、首の傾きは `scene/concierge-finish.ts` が担当。`scene/concierge-rig.ts` がアニメーションミキサーの後に表情を重ねる。
- 正面カメラには回転・ズーム操作を登録しない。モデル上のスワイプはページのスクロールに使える。自動の写真切り替えは行わず、写真ボタンは残す。
- ブラウザが初回音声の自動再生を拒否した場合は「もう一度聞く」を押す。端末の音声・言語設定によって読み上げの可否は異なる。口パクは発話中のリズム表現で、音素単位の同期ではない。
- WebGLやモデルの取得が利用できない場合は写真と案内文を表示する。写真への切り替えで、お辞儀待ちの音声を止め続けない。

検証: `node --test scripts/test-shiro-yado-concierge.mjs`。実際のGLBを読み、動作順序、停止・再生、古いイベントの無視、口の開閉、笑顔と首の傾き、正面の画角を確認する。

ブラウザ検証: `npx playwright test tests/browser/shiro-yado-concierge.spec.ts`（Playwrightを検証環境に用意し、先に `npm run build` を実行）。PC・スマートフォン、明暗テーマ、停止・再生、写真への切り替え、モデル取得失敗時の表示を確認する。音声エンジンはテスト用に置き換えており、端末の実音声は実機で確認する。

## 歓迎体験の改善（2026-10-15）

- 最初に島の景色と「お部屋でゆっくり」「湯にほどける」「島を少し歩く」を表示。自動で切り替わる宣伝スライドはホームから外しました。
- ホームで部屋設定を変更でき、ホーム・経路画面で案内の出発地点を選べます。部屋の変更で現在地は勝手に変わりません。予約・実際のチェックイン処理とは区別しています。
- 経路は `buildGuide` に一本化し、音声も同じ手順を読み上げます。左右はエレベーターから廊下を向いた視点で、2D図・3D俯瞰に合わせて201/202が左、203が正面、204/205が右です。表示の扉名で最終確認します。実在する施設の経路としては使わないでください。
- 6言語の施設情報を用意。日本語の浴場説明は `hotel-data.ts` を単一の原本とし、古い説明の上書きを解消しました。
- 地図にキーボード操作できる番号ボタンを配置。選択後は説明見出しにフォーカスし、音声は別ボタンから再生します。ホーム表示・再訪時に勝手に読み上げません。
- 画面遷移時に見出しへフォーカス。下部ナビの二重選択を修正。明暗テーマ・小さい画面・セーフエリアを考慮しています。
- モデル取得に15秒の期限、発話前のお辞儀に16秒の期限を設けました。取得失敗や動きを抑える設定では写真を使い、館内3Dの失敗時は浴場壁画またはフロア図を表示します。画面外では常時描画を止め、静止シーンは必要時のみ描画します。

### 検証

```sh
npm ci
# 非公開CandleCoreの準備はリポジトリ共通の手順に従う
npm run build
npm run test:shiro-yado
npx playwright install chromium
npm run test:browser:shiro-yado
```

`test:shiro-yado` は13件。全6言語×81経路、204号室の左右、同階移動、到着済み、多言語説明、実GLBのお辞儀・口・笑顔、音声の中断・タイムアウトを確認します。
ブラウザテストは320px暗色・1280px明色の歓迎/部屋設定/到着/地図/言語変更と、390px暗色・1280px明色のモデル制御を含みます。既存のChromiumを使う場合は `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` を指定できます。

今回の実行環境では全体ビルド・対象ソースのlint・13件のロジック/モデルテストが成功しました。ブラウザテストは `socket() failed: Operation not permitted` によりChromium起動前に停止したため、画面の描画・レスポンシブの実測・実音声は未確認です。CDNのブラウザZIP取得にも失敗し、代替配布元からChromium 134を取得して起動を試しましたが同じ環境制約で停止しました。環境制約をアプリの不具合として扱わず、通常の開発環境で上記コマンドを再実行してください。

今後の改善候補: おすすめコースからの複数スポット選択、部屋/浴場の視点プリセット、実端末での音声品質・GLB読み込み時間の評価。写真への自動フォールバック時のモード選択表示も、実機検証と合わせて改善する余地があります。

### ライブラリ調査メモ

浴場壁画の `useTexture()` 戻り値をEffectで変更していた既存コードは、`react-hooks/immutability` に違反していました。インストール済みDreiの `core/Texture.d.ts` と `core/Texture.js` で、第二引数の `onLoad(texture)` がレイアウトEffectで実行され、GPU初期化前に設定できることを確認しました。色空間・異方性の設定を安定した読み込みコールバックへ移しました。無関係なテクスチャ設定や描画色は変えていません。

## 白の宿の見せ方（2026-10-15・利用後のフィードバック）

- 端末の明暗設定によらず、白の宿とページ外周の背景は白に固定します。清潔感と宿のコンセプトを優先する、実験内に限定したテーマ方針です。
- ホームの最上段はコンシェルジュです。続いて島の景色・過ごし方の入口・滞在設定を表示します。
- コンシェルジュ背後の既存ホテル画像は維持し、白いグラデーションの不透明度を下げてホテルの景観が見えるようにしています。写真モードでは既存のフロント写真を表示します。

## 館内ページの改善・第1段階（2026-10-15）

白い背景とホームのコンシェルジュ配置を保ち、経路案内と浴場ページを改善しています。

- 経路案内は出発地・目的地、移動手順、音声と到着操作、館内図の順に表示します。出発地点の変更と到着先の3Dは、必要なときに開く折りたたみです。
- ロビーから出発するときは「ロビー奥のエレベーターホールへ」と案内します。ロビーでも「入口を出て戻る」と読んでいた共通文を、全6言語で修正しました。
- 音声ボタンは画面と同じ手順を読み上げます。自動再生はせず、出発地点の変更・到着・ページ移動で停止します。ミュート・非対応・発話エラーにはテキストの補足を表示します。
- 浴場ページの上部には利用時間・場所・行き方を配置し、続いて既存の富士山と松の壁画、檜の内湯、洗い場と休憩ベンチを紹介します。営業時間・設備は既存の施設データに基づき、未確認の入浴ルールやタオル提供は断定していません。
- `SceneDisclosure` は開いたときだけ3Dをマウントします。3Dが利用できない場合は、壁画・館内図を通常の案内として見せ、再試行を補助操作にしています。

検証: 準備済みの依存関係で `npm run --ignore-scripts build`（TypeScript + Vite）、白の宿と関連テストのESLint、`npm run test:shiro-yado` の16件が成功。新規テストはロビー出発文の6言語確認、Reactのサーバー描画での浴場/経路の情報順と初期表示に3Dが不要なことを確認します。

ブラウザテストには320px暗色/1280px明色、案内の読み上げ・出発地変更時の停止・到着、浴場の情報順・フランス語表示を追加しました。今回のローカル実行は指定したChromium実行ファイルが存在せず起動前に停止したため、ブラウザテストの成功は主張していません。`npx playwright install chromium` 後、`npm run test:browser:shiro-yado` で実行できます。以前の部屋案内テストも折りたたみ操作に合わせて更新しています。

## 体験用の宿泊予約（2026-10-15）

客室詳細、2階の客室一覧、お部屋設定から「空室・料金を見る」「ご予約内容」へ進めます。先頭ページの内容とコンシェルジュの配置は変えていません。

- チェックインは日本時間の今日から1か月後の同日まで。翌月に同日がない場合は月末まで。宿泊は1〜7泊、人数は1〜4名で、各室の定員を守ります。最終チェックイン日から7泊することもできます。
- 201〜204は2名、205は4名まで。架空の税込1室1泊料金は201/202が12,000円、203が16,000円、204が18,000円、205が22,000円です。人数ではなく泊数を掛けて合計を表示します。
- 架空の満室日は部屋と宿泊日の固定式で決まり、再検索で変わりません。すべての宿泊日を調べ、チェックアウト日は占有しません。
- 日程検索→客室選択→内容確認→確定の順で進みます。確定直前に保存済み予約を再読込して空室を再確認し、同じ確定要求の再送は予約を増やしません。
- 予約番号・宿泊内容・料金・確定/取消状態を `localStorage` の `shiro-yado-bookings-v1` に保存します。予約一覧では再読み込み後も確認でき、確認操作を経てキャンセルすると空室に戻ります。
- 名前・連絡先・決済情報は集めず、実際の宿泊・決済・メール送信は行いません。「体験用の予約」を各段階で表示し、同じブラウザ内だけの保存であることを案内します。
- 保存拒否・容量不足・破損した保存データがある場合は、成功表示をせずデータを上書きしません。6言語の操作・エラー表示に対応します。
- 予約完了・予約一覧の「このお部屋の館内案内を見る」は、明示的な操作で案内用の部屋を設定します。予約しただけで現在地や部屋設定を変えません。

実装は `booking/model.ts`（日付・定員・料金・空室）、`storage.ts`（確定/取消）、`use-bookings.ts`（ブラウザ内の変更通知）、各画面に分離しています。Web Locks対応環境では同一オリジン内の確定/取消を排他処理します。非対応環境のフォールバックは同期の再確認・保存で、複数タブの同時操作に対する厳密な原子性は保証しません。実際の共有予約へ発展させる際は、サーバー側のトランザクションが必要です。

検証: `npm run --ignore-scripts build`（準備済み依存関係によるTypeScript+Vite）、ESLint、`npm run test:shiro-yado` の28件が成功。日本時間・月末/うるう年、日付の前後、7泊上限、定員、期間重複、途中日の満室、合計金額、確定の再送、最新データでの再確認、キャンセル、保存失敗/破損データと既存館内案内を検証しています。

Playwrightには予約→再読み込み→確認→キャンセル→再検索、2タブ競合、保存失敗、フランス語、320px/1280pxの5ケースを追加しました。`npx playwright test tests/browser/shiro-yado-booking.spec.ts --list` で認識を確認。ローカルではChromiumが未導入のため、ブラウザの自動操作テストは起動前に停止します。通常環境では `npx playwright install chromium` 後、`npm run test:browser:shiro-yado` で実行できます。

### 予約への入口と客室選び

- トップはコンシェルジュの直下に「空室・料金を見る」と「お部屋を見て選ぶ」を配置。白い背景・フロント背景・コンシェルジュ先頭の構成を維持。
- 下部の「客室・予約」は案内用の客室設定に関係なく `/rooms` へ遷移。滞在中の客室設定は「お部屋への案内」(`/checkin`) として分離。
- 客室一覧・詳細に、配置を保証しない旨を添えた客室イラスト、定員、広さ、1室1泊の架空料金を掲載。客室ごとの検索へ接続。
- 検索結果・確認画面は曜日付きの日付を表示。満室時は人数・泊数を維持して、受付期間内の近い空き日程を最大3件提示し、再検索できる。
- 予約完了から浴場と周辺案内へ進める。日本語を含む6言語に対応。
